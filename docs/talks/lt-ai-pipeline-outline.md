## ストーリー全体

「AI が個別に賢くても、チームとして自律的に動かなければ価値が出ない」を起点に、**個人 OSS kobaamd を 21 日間 AI 任せで作った経験**を **3 つのフェーズ**で語る。各フェーズで見えた**発見**と、それに対する**対処**を積み上げ、Phase 3 で「これから磨いていく QCD」へ繋ぐ。

聞き手の持ち帰り：「**自分も AI を新しいメンバーとして迎え入れ、仕組みで育てていける**」と感じてもらう。

### 4. 【Phase 1】まず AI と一緒に作ってみる
ヘッダ：**Phase 1 ─ まず AI と一緒に作ってみる**（進行バー ●○○）
本文：3 つの AI を役割分担して走らせる
- **Gemini**＝リサーチ・調査（マルチモーダル・大量入力・最新検索）
- **Codex CLI**＝実装の主力（コーディング特化・単価安・ChatGPT Plus 認証）
- **Claude**＝オーケストレーター（設計判断・推論力・コードレビュー）

→ 「特徴を見て、得意領域に当てはめた」というアサイン根拠を併記

### 5. 発見①：能力の高い AI ほど、放っておくと抱え込む
エピソード：「あれ？最近 Codex に頼んでる雰囲気がない…」「Claude さん、実装どうしてる？」「→ 私が書きました！」

新しい比喩（前向き）：
**能力の高いメンバーは、放っておくと "自分でやった方が早い" と判断する。それは AI も同じ。**

→ AI の能力に応じた**役割の固定化**が必要

### 6. 対処：役割を `CLAUDE.md` に明文化する
コードと同じくレビュー可能な場所にルールを置く
- Claude はコードを書かない／実装は Codex／調査は Gemini
- 効果：① Claude が抱え込まなくなる ② モデル単価最適化が効く ③ 新しい session でもルールが効く（再現性）／ルール変更が PR で議論できる

→ **役割が固定されると、AI は本来の強みを発揮する**

### 7. 発見②：対話型では、人間が必ず間に入る
あるあるな1日（6 つ）：
1. Claude「次どうしますか？」で作業中断
2. PR が3つ溜まってる、レビューが追いつかない
3. 通知でチラ見 → 5 分でも作業に戻れない
4. 「あと一周だけ」で午前2時まで止まらない
5. テスト失敗の原因切り分けは結局自分
6. 曖昧質問への待機状態が積み重なる

→ Cursor / Buddy / Claude Code、すべて『対話型』。**仕組みで置き換える必要が見えた**（Phase 2 への動機）

### 8. 【Phase 2】仕組みで AI チームを伸ばす
ヘッダ：**Phase 2 ─ 仕組みで AI チームを伸ばす**（進行バー ○●○）
本文：自律パイプラインの規模感
- **SubAgent 13 / Slash Command 28 / 定期実行 3 バンドル**
- 2026-04-30 にパイプライン基盤を投入。稼働後 **遷移 197 / 書込 560 / Done 31+**
- **人間がやるのは 2 つだけ**：① やりたいことを投げる ② 優先順位をつける

### 9. パイプラインの全体像（ステータスフロー4段図）
4 段構造：
1. 人間の判断ポイント（todo 昇格／Human in Review への返信）
2. ステータスフロー（draft → ... → Done。**通常は Human in Review を通らずに Reviewed → Done**）
3. SubAgent 群（個別の箱、各ステータスに紐付け、利用 Slash 名を併記）
4. 成果物 PRD / Wiki / Postmortem（OUT/IN を矢印と注釈で明示。ADR は Phase 0 の人間記録のみ）

### 10. 育成期：詰まりは仕組みを育てる材料
4 つの実例（**ネガに見せず "育成材料" として提示**）：
- **状態ループ**：KMD-145 ─ In Progress ↔ Todo を 5 回往復（コメント原文引用）
- **コメントスルー**：KMD-119 ─ 72 時間以上停滞
- **トークン枯渇で停止**：想定外の中断
- **デグレ気付かず**：ビルド通ればヨシとなりがち

→ **詰まりごとに、仕組みを育てる材料が見つかる**

### 11. 課題 → 対応：仕組みを育てる 3 軸
| 課題 | 対応 |
|---|---|
| SubAgent が起動するたびに**プロジェクト文脈を持っていない** | **LLM-Wiki を整備**（Prompt Caching 経由で即座に文脈共有） |
| **token がすぐ尽きる** | **Prompt Caching・参照削減・軽量モデル併用**（Sonnet / Haiku） |
| **同じ詰まりを別 issue で繰り返す** | **Postmortem を learnings に記録 → Wiki に ingest**（再利用可能な知見化） |

★限界：**E2E の UX 評価は AI にできない**。「動く」と「使える」は違う。最後は人間が触らないと判断できない領域がある（次フェーズへの橋渡し）

### 12. 本質的発見：AI を伸ばすのは、人間の任せ方
3 つの気付き：
1. **指示が曖昧だと出力も曖昧** → 期待値とゴールを言語化する
2. **手順を渡さないと逐次質問される** → 手順は外在化する（md に落とす）
3. **AI には積み重ねの記憶がない** → 記憶を毎回プロンプトで再現する

新しい比喩（前向き）：
**新人エンジニアと同じ。期待値を伝え、手順を渡し、引き継ぎ書を残す。それが AI でもチームを伸ばす条件。**

→ 対処：**仕事の手順を Slash Command / SubAgent（つまり md）に落とした**。再現可能な「育て方」に変えた

---

### 13. 【Phase 3】QCD を磨く
ヘッダ：**Phase 3 ─ QCD を磨く**（進行バー ○○●）
これからの 3 つの挑戦：
- **Quality**：E2E の UX 検証を Gemini あたりに任せる（"動く" と "使える" のギャップを埋める）
- **Cost**：軽量モデル（Sonnet / Haiku）併用で token 消費を最適化
- **Delivery**：「人間が判断すべきか？」を疑い続け、人間ゲートをさらに減らせないか問う

→ 「**走らせながら、品質・コスト・納期を磨く**」

---

### 14. 伝えたい 3 つのこと
1. **AI を道具と思わず、人だと仮定して仕組みを作ろう**
2. **AI が伸び悩んだら、仕組みで支えよう**
3. **急に振りすぎない。優先順位をつけて渡そう**

→ 「**結局、AI Agent も、人間のチームと同じように育てていく**」

### 15. 最高の AI Agent チームへの旅は続く
メイン：**AI マネジメントは、より良い任せ方を磨いていく旅**
