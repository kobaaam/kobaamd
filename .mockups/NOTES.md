# プロトタイプ検証メモ — kobaamd リコンセプト

## 問い
ターミナルを開きながら成果物をviewする構成として、どのレイアウト/動線が良いか？

## 検証したもの
- `terminal-viewer-layouts.html` — レイアウト比較（A 左右 / B 上下 / C 3ペイン / D ドロワー / E セッションレール / E1 二段レール / E2 デュアル / F ナビ切替 / G 成果物カード）
- `prototype-e1-flow.html` — E1の動線を実際に触れる対話プロトタイプ

## 結論（2026-05-29）
**採用: E1「二段レール」レイアウト。**

- レイアウト = 左ペイン上下2段（上 Sessions / 下 worktreeスコープFiles）｜中 Terminal ｜右 Viewer(md/D2/diffタブ)
- **セッション = git worktree 単位**（Conductor/Crystal 型の物理分離）で確定
- ファイルツリーは worktree にスコープ。横断探索はほぼ不要 → 稀なケースは ⌘P ファジー検索で吸収
- 動線「セッション切替でターミナル履歴・ツリー・ビューアが連動入替」「生成→ツリー出現→表示」は触って良好と判断

### なぜ E1 か（競合比較の要点）
- 非IDE系エージェントツール（Warp / Conductor / Nimbalyst）は揃って「左＝ファイル」ではなく「左＝セッション」に収斂
- kobaamd の差別化 = worktreeセッション × **md・知識成果物特化**（既存の D2図/タグ/backlink/Confluence sync 資産）
